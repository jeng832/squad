# Squad 구성 예시

## 예시 1: 번역-요약 Squad

한글 텍스트를 영어로 번역한 뒤 요약하는 Squad 구성 예시.

### 구성 요소

| 에이전트 | 역할 유형 | 설명 |
|---------|----------|------|
| 번역-요약 오케스트레이터 | ORCHESTRATOR | 번역 → 요약 순서로 작업 분배 |
| 영어 번역기 | WORKER | 한글을 영어로 번역 |
| 영어 요약기 | WORKER | 영어 텍스트를 3~5문장으로 요약 |

### 실행 흐름

```
사용자 프롬프트 (한글 텍스트)
  → 오케스트레이터 → 영어 번역기에게 번역 요청
  → 번역 결과 수신
  → 오케스트레이터 → 영어 요약기에게 요약 요청
  → 요약 결과 수신
  → 오케스트레이터가 최종 결과 조합 → 세션 완료
```

---

### 1단계: Orchestrator Agent 생성

```
> /agent create
```

| 순서 | 프롬프트 | 입력값 |
|------|---------|--------|
| 1 | 이름 | `번역-요약 오케스트레이터` |
| 2 | 역할 유형 선택 | `ORCHESTRATOR` (화살표키) |
| 3 | 시스템 프롬프트 입력 방법 | `직접 입력` (화살표키) |
| 4 | 프롬프트 | 아래 참고 (*빈 줄 2번으로 완료*) |
| 5 | LLM Provider | Enter (기본값 `claude`) |
| 6 | LLM 모델 | Enter (기본값 `claude-sonnet-4-20250514`) |
| 7 | API Key | Enter (건너뛰기) |
| 8 | 생성하시겠습니까? | `예` |

**프롬프트 내용:**
```
사용자의 한글 텍스트를 받아 처리한다.
1. 먼저 "영어 번역기" 에이전트에게 영어 번역을 요청한다.
2. 번역 결과를 받으면 "영어 요약기" 에이전트에게 요약을 요청한다.
3. 두 결과를 합쳐서 최종 결과를 반환한다.
```

| 4 | 프롬프트 | `한글 텍스트를 자연스러운 영어로 번역한다. 원문의 의미와 뉘앙스를 최대한 살려서 번역하며, 번역 결과만 반환한다.` |
| 5 | LLM Provider | Enter |
| 6 | LLM 모델 | Enter |
| 7 | API Key | Enter |
| 8 | 생성하시겠습니까? | `예` |

### 4단계: Squad 생성

```
> /squad create
```

| 순서 | 프롬프트 | 입력값 |
|------|---------|--------|
| 1 | 이름 | `번역-요약 Squad` |
| 2 | 설명 (선택) | `한글을 영어로 번역하고 요약하는 팀` |
| 3 | Orchestrator 선택 | `번역-요약 오케스트레이터` (화살표키) |
| 4 | 멤버 Agent 선택 | `영어 번역기` + `영어 요약기` (스페이스바 토글 → Enter) |
| 5 | 직접 통신 JSON | `건너뛰기` (화살표키) |
| 6 | 생성하시겠습니까? | `예` |

---

### 5단계: 세션 시작

```
> /session start
```

| 순서 | 프롬프트 | 입력값 |
|------|---------|--------|
| 1 | Squad 선택 | `번역-요약 Squad` (화살표키) |
| 2 | 프롬프트 | 번역/요약할 한글 텍스트 (*빈 줄 2번으로 완료*) |
| 3 | Git 저장소 URL | Enter (건너뛰기) |
| 4 | 세션을 시작하시겠습니까? | `예` |

**프롬프트 예시:**
```
다음 글을 영어로 번역하고 요약해줘:

인공지능은 최근 몇 년간 급격한 발전을 이루었다.
특히 대규모 언어 모델의 등장으로 자연어 처리 분야에서
획기적인 성과를 보이고 있다. 이러한 기술은 번역, 요약,
코드 생성 등 다양한 분야에서 활용되고 있다.
```

---

### 6단계: 결과 확인

```
> /session monitor 1    ← 실시간 모니터링
> /session result 1     ← 완료 후 결과 조회
```

## 예시 2: Squad 코드 분석 응답 Squad

현재 `squad` 레포를 워크스페이스에 clone한 뒤, 코드 구조를 분석하고 개선 포인트를 정리해주는 Squad 구성 예시.

### 구성 요소

| 에이전트 | 역할 유형 | 설명 |
|---------|----------|------|
| 코드 리뷰 오케스트레이터 | ORCHESTRATOR | 분석 질문을 분해하고 결과를 취합 |
| 백엔드 분석가 | WORKER | Spring/도메인/서비스 레이어 분석 |
| 인프라 분석가 | WORKER | Docker/런타임/배포 흐름 분석 |
| 문서화 담당 | WORKER | 답변을 실행 가능한 액션 아이템으로 정리 |

### 실행 흐름

```
사용자 질문
  → 오케스트레이터가 분석 관점 분해
  → 백엔드/인프라 분석가에게 병렬 요청
  → 결과 수신
  → 문서화 담당이 핵심 요약/우선순위 정리
  → 오케스트레이터가 최종 답변 반환
```

---

### 1단계: Agent 생성

`/agent create`를 이용해 아래 4개 Agent를 생성한다.

| 이름 | 역할 유형 | 시스템 프롬프트 예시 |
|------|----------|----------------------|
| 코드 리뷰 오케스트레이터 | `ORCHESTRATOR` | `요청을 분석 단위로 분해하고 적절한 에이전트에게 작업을 위임한다. 최종 응답은 근거 파일 경로와 함께 작성한다.` |
| 백엔드 분석가 | `WORKER` | `Java/Spring 코드 중심으로 구조, 의존성, 잠재 결함, 테스트 공백을 분석한다. file_search, file_read, bash_exec를 활용한다.` |
| 인프라 분석가 | `WORKER` | `Dockerfile, compose, 실행/배포 흐름, 운영 리스크를 분석한다. 필요한 경우 설정값과 포트를 명시한다.` |
| 문서화 담당 | `WORKER` | `수집된 분석을 1) 핵심 이슈 2) 영향도 3) 다음 액션 순서로 간결하게 정리한다.` |

---

### 2단계: Squad 생성

```
> /squad create
```

| 순서 | 프롬프트 | 입력값 |
|------|---------|--------|
| 1 | 이름 | `Squad 코드 분석 Squad` |
| 2 | 설명 (선택) | `squad 레포 구조 분석 및 개선 제안` |
| 3 | Orchestrator 선택 | `코드 리뷰 오케스트레이터` |
| 4 | 멤버 Agent 선택 | `백엔드 분석가`, `인프라 분석가`, `문서화 담당` |
| 5 | 직접 통신 JSON | `건너뛰기` |
| 6 | 생성하시겠습니까? | `예` |

---

### 3단계: 세션 시작 (Git Clone 포함)

```
> /session start
```

| 순서 | 프롬프트 | 입력값 |
|------|---------|--------|
| 1 | Squad 선택 | `Squad 코드 분석 Squad` |
| 2 | 프롬프트 | 아래 분석 요청 예시 입력 |
| 3 | Git 저장소 URL | `https://github.com/jeng832/squad` |
| 4 | 브랜치 | `main` |
| 5 | 세션을 시작하시겠습니까? | `예` |

**프롬프트 예시:**
```
이 레포의 세션 시작 경로(SessionExecutionService)를 중심으로
1) 실패 가능 지점
2) 운영에서 발생할 수 있는 리스크
3) 우선순위 기준 개선안 5개
를 파일 경로와 함께 정리해줘.
```

---

### 4단계: 결과 확인

```
> /session monitor {id}
> /session result {id}
```

결과 확인 시 체크할 포인트:
- 파일 경로를 근거로 들었는지
- 개선안이 우선순위/영향도 기준으로 정렬됐는지
- 바로 작업 가능한 단위(작업 항목)로 제시됐는지
